CLOUD STORAGE

Cloud sync and local NAS

Choose an archive destination or provision a separate RBE node. Provider sign-in and peer pairing are shown only where the current implementation supports them.

Google Drive

Use a Google Drive for desktop synced folder as a local archive destination.

G

Direct Google Account OAuth and Drive API upload are not wired into GitManager yet. For now, install Google's desktop sync client, choose its local mirrored folder in Scan Setup, and store local archive copies there.

This is local-folder storage through the Google sync client, not a direct Drive API connection.

Microsoft OneDrive

Use a OneDrive synced folder as a local archive destination.

☁

Direct Microsoft Account OAuth and Graph API upload are not wired into GitManager yet. For now, use the OneDrive desktop client's local folder as an archive destination in Scan Setup.

This is local-folder storage through the OneDrive sync client, not a direct Microsoft Graph connection.

Supabase Storage

Connect an object bucket using the existing RBE provider-backed archive engine.

S

Supabase Storage is supported through provider configuration. The API key stays in the GitManager process environment as RBE_CN_PROV_SUPABASE_API_KEY; it is not stored in the provider JSON.

Azure Blob Storage

Use an Azure Storage container with a SAS token from your operating system environment.

AZ

The provider uses the account name and container (bucket) below. Store the SAS token in RBE_CN_PROV_AZURE_SAS_TOKEN; the token is never saved in GitManager's JSON settings.

Google Cloud Storage

Connect a GCS bucket using an OAuth bearer token from your environment.

GCS

This is Google Cloud Storage, not Google Drive. Supply a valid access token through RBE_CN_PROV_GOOGLE_OAUTH_TOKEN. Direct Google Drive API upload remains separate and is not implemented here.

Amazon S3

Use a bucket with the native S3 SigV4 provider.

S3

The provider reads credentials from RBE_CN_PROV_AMAZON_ACCESS_KEY and RBE_CN_PROV_AMAZON_SECRET_KEY, with an optional session token. Credentials are not written into GitManager settings.

S3-compatible storage

Use a custom endpoint with AWS SigV4 request signing.

⇄

The Amazon S3 adapter accepts a custom endpoint and uses path-style bucket URLs with SigV4 signing. This works with S3-compatible services that implement that request format. Set RBE_CN_PROV_AMAZON_ACCESS_KEY and RBE_CN_PROV_AMAZON_SECRET_KEY in the operating system environment; use the endpoint and region value supplied by your storage vendor.

Custom HTTPS object storage

Use the existing generic HTTP object adapter for a compatible object API.

HTTPS

Configure the HTTPS endpoint and use RBE_CN_PROV_HTTP_BEARER_TOKEN by default. The generic adapter is not guaranteed to support every vendor's proprietary API or authentication scheme.
